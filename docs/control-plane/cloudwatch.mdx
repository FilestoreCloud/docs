# Observability & Synthetics Canaries

The Storix platform incorporates a defense-in-depth observability architecture spanning real-time metric emission, structured log streaming, Container Insights, and automated Synthetics Canary SLA probing.

---

## 🕊️ CloudWatch Synthetics Canaries (24/7 SLA Probes)

Module `07-observability` deploys an automated canary (`AWS::Synthetics::Canary`) executing continuous end-to-end health assertions against the platform:

```yaml
StorixSyntheticsCanary:
  Type: AWS::Synthetics::Canary
  Properties:
    Name: !Sub "${EnvironmentName}-storix-health-canary"
    RuntimeVersion: syn-nodejs-puppeteer-9.1
    Schedule:
      Expression: "rate(5 minutes)"
    ArtifactS3Location: !Sub "s3://${CanaryArtifactsBucket}"
```

### Key Canary Verifications

1. **HTTP Status Code Verification:** Confirms `/status.php` and health endpoints return strict `200 OK`.
2. **Response Latency Logging:** Emits precise DNS lookup, TCP handshake, TLS negotiation, and first-byte latency metrics into CloudWatch EMF.
3. **Content Integrity Verification:** Validates JSON response bodies for `{"installed": true, "maintenance": false}`.
4. **Automated Alarm Triggering:** Dispatches immediate SNS alerts if more than 1 probe failure occurs within a 15-minute window.

## 📊 Embedded Metric Format (EMF) & Telemetry

The Control Plane Lambda emits CloudWatch metrics using **AWS Embedded Metric Format (EMF)** directly to stdout, eliminating external API latency and throttling risks:

```json
{
  "_aws": {
    "Timestamp": 1792341570666,
    "CloudWatchMetrics": [
      {
        "Namespace": "Storix/Platform",
        "Dimensions": [["Environment", "TenantId"]],
        "Metrics": [
          { "Name": "TenantActiveTaskCount", "Unit": "Count" },
          { "Name": "OccCommandExecutionLatency", "Unit": "Milliseconds" }
        ]
      }
    ]
  },
  "Environment": "dev",
  "TenantId": "acme",
  "TenantActiveTaskCount": 1.0,
  "OccCommandExecutionLatency": 142.5
}
```

## 📈 Key Metric Dimensions

| Metric | Namespace | Dimensions | Alert Threshold / Description |
|---|---|---|---|
| `RequestCount` | `AWS/ApplicationELB` | `LoadBalancer` | Total HTTP requests handled by ALB ingress. |
| `HTTPCode_Target_5XX_Count` | `AWS/ApplicationELB` | `LoadBalancer` | Critical alarm triggered if > 5 errors in 3 minutes. |
| `CPUUtilization` | `AWS/ECS` | `ClusterName, ServiceName` | Scale-out triggered if > 70% for 2 consecutive 60s periods. |
| `MemoryUtilization` | `AWS/ECS` | `ClusterName, ServiceName` | Memory pressure tracking per tenant container. |
| `DatabaseConnections` | `AWS/RDS` | `DBInstanceIdentifier` | Monitored through RDS Proxy connection pooling. |
| `CanarySuccessPercent` | `CloudWatchSynthetics` | `CanaryName` | Critical alarm triggered if `< 95%` over 15 minutes. |

## 🪵 Structured Container Log Streaming

Container logs for both Nextcloud Apache/PHP app containers and LiteLLM Bedrock AI Bridge sidecars stream to Amazon CloudWatch:

- **Nextcloud Logs:** `/ecs/<env>-nextcloud` (JSON format, retaining PHP stack traces and audit events).
- **Bedrock AI Bridge Logs:** `/ecs/<env>-litellm` (Request tokens, latency, model routing).
- **Control Plane Audit Logs:** `/aws/audit/control-plane` (Immutable 365-day administrative audit trail).
