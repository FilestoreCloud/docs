# Tenant Provisioning

Storix provisions new tenants using automated **Step Functions SAGA Micro-Workflows** that orchestrate all cloud resource provisioning with complete isolation.

## 🖥️ Via SuperAdmin Console UI

1. Open the **SuperAdmin Console** at `https://admin.png261.dev`.
2. Click the **+ Create Tenant** button in the header or tenants table.
3. Complete the provisioning form:
   - **Tenant ID:** Lowercase alphanumeric identifier (e.g. `acme`).
   - **Organization Name:** Display name (e.g. `Acme Corporation`).
   - **Domain:** Dedicated subdomain (e.g. `acme.png261.dev`).
   - **Admin Email:** Initial organization admin email (synced automatically).
   - **Storage Quota:** Initial storage allocation (e.g. `100 GB`).
4. Click **Submit**. The console tracks live provisioning progress through the Step Functions execution stream.
5. Default administrator credentials are provisioned securely: username `admin`, initial password `StorixAdmin2026!Secure` (stored authoritatively in AWS Secrets Manager).

## ⚡ Via Control Plane API

```bash
curl -X POST https://admin.png261.dev/api \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "PROVISION",
    "tenant_id": "acme",
    "tenant_name": "Acme Corporation",
    "admin_email": "admin@acme.com",
    "domain": "acme.png261.dev",
    "quota_gb": 100
  }'
```

![Step Functions SAGA Tenant Provisioning Workflow](/images/flow_tenant_provisioning_saga.png)

### Compensating Rollbacks
If any step fails (e.g. ECS task fails healthchecks within timeout), the Step Functions state machine executes reverse compensating actions:
- Deletes created EFS Access Point
- Drops created PostgreSQL database catalog
- Purges S3 initial vault prefix
- Deletes created OpenSearch index
- Deletes ALB target group and listener rules
- Marks tenant as `FAILED` in DynamoDB Registry
