# GitHub Actions CI/CD Pipelines

All platform deployments, runtime container builds, console frontend updates, and infrastructure destructions are fully automated via **Native GitHub Actions CI/CD** in [`FilestoreCloud/infra`](https://github.com/FilestoreCloud/infra) using secure **AWS IAM OpenID Connect (OIDC)** authentication (zero static credentials).

---

## 🚀 Full Platform Deployment (`deploy-all.yml`)

The `deploy-all.yml` workflow orchestrates a 10-stage end-to-end deployment across all layers:

```mermaid
flowchart TD
    subgraph ParallelPhase["Parallel Build Phase"]
        R["1. Build & Push Multi-Arch Runtime to ECR<br/>(linux/arm64 + linux/amd64 + AWS SOCI)"]
        N["2a. Deploy 01-Networking Stack<br/>(VPC, Subnets, S3 Gateway Endpoint)"]
    end

    subgraph SecurityPhase["Security & Foundation"]
        S["2b. Deploy 02-Security Stack<br/>(Security Groups, KMS Keys, IAM Roles)"]
    end

    subgraph StorageDataPhase["Storage & Data Tier"]
        ST["2c. Deploy 03-Storage Stack<br/>(EFS Archive Lifecycle & S3 Multi-Tier)"]
        DB["2d. Deploy 04-Database Stack<br/>(RDS PostgreSQL 16 & RDS Proxy)"]
    end

    subgraph ComputePhase["Compute & Control Plane"]
        C["2e. Deploy 05-Compute Stack<br/>(ECS Fargate ARM64, ALB, Dedicated Cron)"]
        SA["2f. Deploy 06-SuperAdmin Stack<br/>(Step Functions SAGAs, Lambda, Async OCC)"]
        OB["2g. Deploy 07-Observability Stack<br/>(Synthetics Canaries & CloudWatch EMF)"]
    end

    subgraph FrontEndAndVerify["Frontend & Verification"]
        CP["3. Build Console React SPA & Deploy to CloudFront"]
        AC["4. Full-Stack Acceptance Tests<br/>(Terratest In-Place + Playwright E2E)"]
    end

    ParallelPhase --> S
    S --> StorageDataPhase
    StorageDataPhase --> C
    C --> SA & OB
    SA & OB --> CP
    CP --> AC
```

### Triggering via GitHub CLI

```bash
gh workflow run deploy-all.yml \
  --repo FilestoreCloud/infra \
  -f environment=dev \
  -f skip_runtime_build=false \
  -f run_acceptance_tests=true
```

## 💥 Zero-Cost Infrastructure Teardown (`destroy.yml`)

To achieve true **$0.00 idle cost** when testing or decommissioning an environment, `destroy.yml` tears down all provisioned resources in reverse dependency order:

```mermaid
flowchart LR
    O["07-Observability"] --> SA["06-SuperAdmin"]
    SA --> C["05-Compute"]
    C --> DB["04-Database"]
    DB --> ST["03-Storage"]
    ST --> S["02-Security"]
    S --> N["01-Networking"]
```

### Triggering Teardown via GitHub CLI

```bash
gh workflow run destroy.yml \
  --repo FilestoreCloud/infra \
  -f environment=dev \
  -f confirm_destruction=DESTROY
```

<Warning>
  Teardown purges all database tables, EFS access points, and test S3 buckets. Always verify you are targeting the appropriate environment before providing `confirm_destruction=DESTROY`.
</Warning>
